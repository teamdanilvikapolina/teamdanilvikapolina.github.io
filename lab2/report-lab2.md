## Задание 3. Кластеризация на эмбеддингах

Эмбеддинги `intfloat/multilingual-e5-small` с префиксом `query:` и `normalize_embeddings=True`, агломеративная кластеризация (`metric="cosine"`, `linkage="average"`).

Ключевая особенность корпуса: **медианное попарное косинусное расстояние — 0,116** (10% квантиль 0,075, 90% квантиль 0,143). Тема узкая: все 1975 запросов про одну Госдуму, поэтому даже далёкие по смыслу запросы лежат близко. Из-за этого пороги верхней части сетки из ТЗ дают вырожденное разбиение:

| Порог | Число кластеров | Силуэт |
|-------|-----------------|--------|
| 0,10 | 59 | 0,190 |
| 0,15 | 1 | — |
| 0,20 | 1 | — |
| 0,25 | 1 | — |
| 0,075 (расширение сетки вниз) | **184** | **0,265** |
| 0,05 (расширение сетки вниз) | 440 | 0,293 |

**Выбранный порог — 0,075.** Обоснование: сетка из ТЗ рассчитана на широкий корпус, а наш — одна тематика с медианным расстоянием 0,116, поэтому порог сдвинут вниз по гистограмме попарных расстояний. При 0,15–0,25 всё склеивается в один кластер («порог слишком велик» из таблицы типичных ошибок); при 0,10 остаются два мега-кластера по ~30% и ~25% корпуса («выборы-2026» и «выборы вообще») — для карты контента они бесполезны; при 0,05 — 119 одноэлементных кластеров. 0,075 даёт 184 кластера (медиана 4 запроса, максимум 543, силуэт 0,265) — это рабочий компромисс; содержательная проверка — в задании 4. Колонка `cluster_emb` добавлена в `core`.

**Дополнительно (HDBSCAN).** `HDBSCAN(metric="cosine")` в режиме EOM: 41 кластер, **шум — 1211 строк (61%)**, силуэт без шума 0,277. `cluster_selection_epsilon` с `metric="precomputed"` в scikit-learn 1.9.1 падает на внутреннем баге `epsilon_search`, поэтому режим EOM без epsilon. Важный вывод: в узком корпусе шум HDBSCAN — это не «кривые строки», а одиночные редкие интенты без близких соседей («выборы в госдуму дэг», «сколько округов в госдуме», «зарплата депутатов госдумы в 2026 году») — для ядра их нельзя выбрасывать, это отдельные маленькие кластеры.

## Задание 4. Честная оценка: силуэт против ручной разметки

По 50 случайных пар внутри кластеров для каждого метода (`random.seed(42)`), файлы обезличены перед разметкой (нейтральные имена `pairs_A`/`pairs_B`, перемешанный порядок), критерий — «эти два запроса должны вести на одну страницу, да/нет». Финальные файлы — **`pairs_emb.csv`** и **`pairs_tfidf.csv`** (по 50 пар с колонками `verdict_1`/`verdict_2`) — генерируются ноутбуком и приложены к нему же в репозитории.

| Метод | Кластеров | Силуэт | Доля «да», проверяющий 1 | Доля «да», проверяющий 2 | Согласие проверяющих |
|-------|-----------|--------|--------------------------|--------------------------|----------------------|
| TF-IDF + K-means | 98 | 0,273 | 0,74 | 0,74 | 1,00 |
| Эмбеддинги + порог 0,075 | 184 | 0,265 | 0,58 | 0,58 | 1,00 |

**Вывод: по этим числам победил бейзлайн** — TF-IDF + K-means даёт и более высокий силуэт (0,273 против 0,265), и заметно более высокую долю «да» (0,74 против 0,58). Силуэт и люди в этом прогоне согласны. Причина видна в самих парах: на узком корпусе K-means нарезает плотные лексические группы (регион, партия, фамилия), внутри которых пары почти синонимичны, а эмбеддинги при пороге 0,075 склеивают смысловые соседи с разными интентами — «выборы в госдуму в нижегородской области» + «госдума нижегородской области» (выборы против органа власти), «коммунисты в госдуме» + «коммунисты россии в госдуме» (КПРФ против отдельной партии). Это ровно те «геометрически аккуратные, но разные по странице» случаи, о которых предупреждало задание.

**Важная оговорка об инструментарии разметки.** Работа выполнялась дистанционно, и ручную разметку фактически выполнял ИИ-ассистент в два независимых прохода (файлы `pairs_A_v1/v2.csv`, `pairs_B_v1/v2.csv` приложены к ноутбуку), а не два члена команды. Согласие 1,00 здесь показывает воспроизводимость одного «мозга», а не субъективность людей: настоящая проверка субъективности — дать файлы `pairs_A.csv`/`pairs_B.csv` Вике и Полине и переметить. Формулировки пар и файлов готовы к этому. Пограничные пары (регион+орган, спикер/вице-спикер, бюллетень/кандидаты в бюллетене) — именно там, где живые проверяющие разойдутся.

Что это значит для турнира: для реальной тематики с частотностями и одной лексической доминантой K-means — честный конкурент. Но для «квазибуплона» бейзлайн неприменим в принципе: слово незнакомо и TF-IDF-словарю, и Вордстату — ядро турнира строится только на эмбеддингах (задание 6).

## Задание 5. Классификация интента

100 случайных запросов (`random_state=7`) размечены четырьмя классами: **info — 94, trans — 3, nav — 2, comm — 1**. Эталонная разметка — [intents.csv](intents.csv); zero-shot разметка того же списка — [zs_intents.csv](zs_intents.csv).

Ограничение, зафиксированное честно: в информационной теме классы перекошены до предела — `comm` встречается 1 раз, поэтому `stratify=y` технически невозможен (минимум 2 представителя класса); `class_weight="balanced"` компенсирует перекос в обучении, но тестовые 30 примеров почти целиком info. Вторая оговорка: обе разметки (эталон и zero-shot) выполнены ИИ-ассистентом, эталон поэтому «условный» — как прямо допускает задание.

**Матрица ошибок — логистическая регрессия на эмбеддингах** (тест 30%, `random_state=42`), строки — эталон, столбцы — предсказание (info/nav/comm/trans):

```
[[24  4  0  1]   info: precision 0,96, recall 0,83, F1 0,89
 [ 1  0  0  0]   nav:  0/0/0 (1 пример)
 [ 0  0  0  0]   comm: нет в тесте
 [ 0  0  0  0]]  trans: нет в тесте
accuracy 0,80
```

**Матрица ошибок — zero-shot ИИ-ассистент** (сравнение с эталоном, те же 100 запросов):

```
[[92  0  0  2]   info→trans: 2
 [ 0  2  0  0]   nav: 2/2 верно
 [ 0  0  1  0]   comm: 1/1 верно
 [ 1  0  0  2]]  trans→info: 1
accuracy 0,97
```

**Какая пара классов путается чаще всего и почему:** info и trans. Оба метода путают «результаты выборов в госдуму 2026 онлайн» (info по эталону, trans по zero-shot), «избирательные округа в госдуму» (info/trans) и «электронное голосование в госдуму 2026» (trans/info). Причина — запросы на границе «узнать» и «сделать»: посмотреть результаты онлайн или найти свой округ — это подготовка к действию, и грань проходит по тому, хочет ли пользователь уже сервис, а не статью. Логрегрессия дополнительно путает info с nav: запросы вида «цик выборы в госдуму 2026» выглядят информационными, но ведут на конкретный ресурс.

**Какой метод возьмём для ядра на 3000 запросов:** zero-shot ИИ-ассистента — по совокупности стоимости и качества: он не требует размечать обучающую выборку (для 3000 запросов вручную это часы), на нашем тесте точнее обученной логрегрессии (0,97 против 0,80 — правда, на перекошенных классах), и его легко перезапустить с фиксированным промптом для воспроизводимости. Логрегрессию оставляем как дешёвый локальный вариант, когда размеченных данных станет много (несколько сотен на класс), — тогда она обгонит zero-shot и перестанет зависеть от внешнего сервиса. Приоритет: стоимость → качество → воспроизводимость.

### Осторожно с нормализацией

Без списка исключений `pymorphy3` угадывает лемму незнакомого слова по-разному: «квазибуплон» → **квазибуплоно**, «квазибуплоны» → **квазибуплона**, «квазибуплонов» → **квазибуплоновый**, «квазибуплона» → **квазибуплоно**. Формы одного термина разъезжаются по трём леммам, и склейка дублей из задания 1 ломается. Лечение — `KEEP`-исключения, все формы сводятся к «квазибуплон». После правки из 44 формулировок нормализуется в 42 уникальные: склейка объединила тройку «определение квазибуплона» / «квазибуплон определение» / «квазибуплона определение» — падежный вариант действительно дубль определения. Отсюда же правило для текста страницы: в тексте нужны естественные фразы с разными падежами термина, а не перечисление словоформ — поисковик лемматизирует сам (и тоже по-своему ошибается на незнакомом слове).
